\subsection{Verification Methodology and Test Architecture}

In accordance with rigorous embedded systems engineering principles~\cite{marwedel,kopetz}, verification was conducted following a dual-tier validation hierarchy:
\begin{enumerate}
  \item \textbf{Host-Platform Automated Unit \& Regression Testbench (PC Level):}
        The core FSM logic (\code{washing_machine_fsm.c}), timing blinkers (\code{hal_led_blinker.c}), switch debouncers (\code{hal_button_engine.c}), and multi-gesture decoders (\code{hal_button_gesture.c}) are compiled natively using host \code{gcc} with strict pedagogical and MISRA compliance flags (\code{-Wall -Wextra -Werror -pedantic -std=c99 -O2}). A high-performance \textbf{Mock HAL} (\code{mock_hal.c}) intercepts all physical peripheral interactions. Logical clock progression is decoupled from physical wall-clock time: a full 30-minute ($1{,}800{,}000$\,ms) wash cycle is simulated in less than $0.8$\,ms of CPU time while guaranteeing deterministic, cycle-accurate event sequencing.
  \item \textbf{Target-Hardware In-System Benchmark (WeAct STM32H750VBT6 Level):}
        The complete bare-metal firmware image is flashed via USB-DFU to the STM32H750 target running at $400$\,MHz. Real-world validation confirms debouncer stability against mechanical switch contact bounce, ST7735 LCD SPI transmission determinism, TIM1 PWM backlight stability, and UART telemetry stream integrity under actual electrical operation.
\end{enumerate}

\subsection{Automated Unit and Regression Test Suites}

The 94 automated unit tests are partitioned across five specialized test executables:
\begin{enumerate}
  \item \textbf{Washing Machine Core FSM Suite (\code{test_washing_machine.c} -- 34 Tests):}
        Exercises all 6 operational states, 22 transitions, conditional guards, arithmetic overflow protections, timer rollover, rapid state toggling, and corrupted enum handling under MISRA-C Rule 16.4 constraints.
  \item \textbf{Hardware Abstraction Engine Suite (\code{test_hal_engines.c} -- 6 Tests):}
        Validates the 30\,ms integrating button debouncer against rapid contact bounce (1\,kHz chatter), verifies the pulse-train coin discriminator and circular burst FIFO, proves phase continuity and zero cumulative drift of the 1.0\,Hz and 2.0\,Hz blinker engines, and tests actuator interlock violations.
  \item \textbf{Single-Key Gesture Recognition Suite (\code{test_gesture.c} -- 32 Tests):}
        Tests multi-gesture temporal classification: short clicks, double-clicks, Stage-1 hold ($600$\,ms), Stage-2 hold ($1200$\,ms), hold-release events, and verifies that the double-stop interval fits deterministically within the FSM window.
  \item \textbf{Two-Button Front-Panel Dashboard Suite (\code{test_two_button.c} -- 18 Tests):}
        Verifies staged coin accumulation, manual threshold confirmation, change refund calculations, and panel command prioritization.
  \item \textbf{UI Text Telemetry Suite (\code{test_ui_text.c} -- 4 Tests):}
        Validates UART formatted status telemetry string generators, bounded buffer safety, and \code{NUL}-termination under MISRA-C Rule 21.3.
\end{enumerate}

\subsection{Sub-Millisecond Boundary Condition Validation}

A prominent advantage of the Mock HAL architecture is the ability to validate temporal boundary conditions with microsecond precision, completely free of human reaction variance.

\paragraph{Boundary Verification of Double-STOP Window (TC-22):}
Functional Requirement FR-08 and Assumption A1 specify that forced termination requires two successive STOP presses within $T_{\text{double}} \le 1500$\,ms. Test case \code{TC-22} validates the exact temporal threshold by driving the simulated clock:
\begin{itemize}
  \item \textbf{Case A ($t = 1499$\,ms):} The second press is injected exactly $1499$\,ms after the first. Guard condition $(1499 \le 1500)$ evaluates to TRUE: the system immediately forces state transition to \code{STANDBY}, cancels the motor, and unlocks the door.
  \item \textbf{Case B ($t = 1501$\,ms):} The second press arrives $1501$\,ms after the first. Guard condition $(1501 \le 1500)$ evaluates to FALSE: the previous press has expired. The second press is registered as a fresh first press; the machine remains in \code{RUNNING} mode without interruption.
\end{itemize}
This sub-millisecond precision proves mathematical determinism of the control core.
