\section{Finite State Machine Design}
\label{sec:fsm}
% =============================================================================

\subsection{Model}

The controller is an \textbf{extended FSM} with 6 states and the context variables
\begin{center}
$b$ = \code{coin_balance_cents},\quad
$t$ = \code{remaining_cycle_sec},\quad
$n$ = \code{stop_press_count},\quad
$w$ = \code{stop_window_timer_ms},\quad
$T$ = cycle length (1800\,s).
\end{center}
LED outputs depend only on the state (Moore outputs, Table~\ref{tab:moore}); the updates of $b$,
$t$, $n$ and the coin return are attached to transitions (Mealy actions, Table~\ref{tab:transitions}).
Notation on the diagrams: \textit{event [guard] / action}; COIN($v$) stands for any of the three coin
events with value $v \in \{10, 20, 50\}$.

\noindent \textbf{Ignored events.} Every (state, event) pair that is not in Table~\ref{tab:transitions}
is ignored, e.g.\ RUN/PAUSE/STOP in STANDBY, RUN in COLLECTING (not enough money), PAUSE in READY,
coins in RUNNING/PAUSED/ERROR, all buttons in ERROR. \code{wm_fsm_dispatch_event()} returns
\code{false} for these and the outputs do not change.

\subsection{Design remarks}

\begin{itemize}
  \item \textbf{Why the timer is a variable and not a state.} 1800 states would be absurd; a counter
        with guards $t > 1$ / $t = 1$ keeps the diagram small and lets RUNNING and PAUSED share the
        same countdown code (T10/T15), which guarantees FR-06.
  \item \textbf{Why ERROR has priority.} The FAULT event is checked \emph{before} the state switch in
        \code{wm_fsm_dispatch_event()}, so no state can ``forget'' to handle it.
  \item \textbf{Why STOP needs a counter.} The double press is a small sub-machine ($n \in \{0,1\}$ plus
        the window $w$) embedded in every state that accepts STOP. It is reset whenever the machine enters
        STANDBY, COLLECTING, RUNNING, PAUSED or ERROR, so a first press made before RUN or PAUSE can
        never combine with a press made after it.
\end{itemize}
