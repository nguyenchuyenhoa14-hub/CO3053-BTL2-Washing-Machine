\subsection{One time base, no blocking delay}

\code{HAL_Delay()}-style waiting would freeze the controller: during a 500\,ms delay for blinking, a
button press or a coin could be lost and the 30-minute timer would drift. Instead, every timing in the
system is a \textbf{counter advanced by a 1\,ms tick}:

\begin{itemize}
  \item The SysTick interrupt does only one thing: \code{g_millis++}. It is short, cannot block and
        shares no other data with the main loop, so no critical section is needed.
  \item The main loop compares \code{board_millis()} with the last processed millisecond and calls
        \code{process_1ms()} \emph{once per elapsed millisecond}. If the loop was busy (e.g.\ pushing a
        25\,KB frame to the LCD takes a few ms), it catches up the missing milliseconds in order, so no
        tick is lost and all timers stay exact.
  \item \code{process_1ms()} advances, in a fixed order: the STOP window, both LED blinkers, the
        debouncers, the gesture decoders, and a millisecond accumulator that produces the 1\,s tick every
        1000 calls.
\end{itemize}

\subsection{The 30-minute timer}

The timer is the context variable \code{remaining_cycle_sec}. RUN in READY loads it with
\code{cycle_duration_setting} (1800\,s). Each 1\,s tick decrements it by one; when it goes from 1 to 0
the FSM calls \code{on_cycle_complete()} and enters STANDBY. Because the 1\,s tick is generated by
counting exactly 1000 SysTick periods, the accuracy of the timer equals the accuracy of the 25\,MHz
crystal (typically $\pm$\,20\,ppm, i.e.\ $< 0.04$\,s over 30\,min).

\subsection{Timer keeps running in PAUSED}

The same handler \code{handle_1s_timer_tick()} is called from both RUNNING and PAUSED
(transitions T10 and T15). The only difference is that RUNNING also updates the actuators for the current
phase, while PAUSED leaves them off. Therefore pausing \emph{cannot} stop the timer, and a cycle that is
paused until $t = 0$ ends in STANDBY exactly as a running one (T16, test TC-08).

\subsection{LED blinking}

The FSM only sets a \emph{mode} (\code{HAL_LED_BLINK_1HZ}, \dots). The blinker keeps a phase accumulator
and toggles the output every half-period:
\[
  f_\text{BLED} = \frac{1}{2 \times 500\,\text{ms}} = 1\,\text{Hz}, \qquad
  f_\text{RLED} = \frac{1}{2 \times 250\,\text{ms}} = 2\,\text{Hz}.
\]
Changing the mode restarts the phase with the LED ON, so the first blink after entering RUNNING is always
a full 500\,ms ON. If a large time step is passed (\code{delta_ms} $\gg$ period), the number of toggles is
computed with a modulo so the ON/OFF parity is preserved (no drift, test HAL-03).

\noindent The first STOP sets $n := 1$ and $w := 1500$. Every millisecond $w$ is decremented; when it
reaches 0, $n$ is reset and the first press is forgotten. A STOP that arrives while $n = 1$ is the
confirmed second press and forces the stop. The boundary is tested at 1499\,ms (stop) and 1501\,ms (no stop)
in TC-22. Washing and the timer are not affected by the first press.
